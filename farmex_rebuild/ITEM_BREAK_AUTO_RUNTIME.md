# Owned automatic item-break worker bridge

The actual auto checkbox starts/stops100ms Tk polling of
`ItemBreakRequestCycleFrame`. It controls the own timer only. Native settings
callback/initialization gate and upstream dispatcher mode5 are not executed;
post-prologue entry, bot gate, source enable and both work-byte reads remain
independent supplied observations. A checked box never implies those captures.

An optional synchronous `auto_item_break_provider(context)` returns typed
`AutoBreakInput` with guard, NPC, request and separate parent receipts. Current
panel enable/speed/Abyss values are exposed as configuration information; they
are not substituted for fresh native fields or source parser results. Missing
provider waits without inventory/NPC/clock/helper success guesses.

Guard completion does not infer the fresh second work byte. Source stop and
notice returns remain separate; a supplied stop return does not uncheck the
own checkbox or certify native BotSwitch effects. Successful NPC paths reach
the existing signed QWORD clock/lowDWORD speed*1000 comparison. Request child
and parent return precede the independent second clock, its stores and caller
return. Equal thresholds, negative speed and DWORD rollover retain the source
model's signed behavior.

Completed own clock writes survive tick and checkbox stop/restart. Later read
gaps bind that own stamp; a conflicting supplied stamp is held only when that
field is reached. Unreached captures cannot force a conflict, and a stale
sample cannot reset cooldown to zero. Profiles reset this own state epoch.
This is a consistent own single-thread state model, not native race handling.

Manual and automatic paths share a scalar shadow and packet queue. Each
invocation applies only new NPC/clock store prefixes, so polling an old pending
path cannot overwrite a newer store from the other path. New packet prefixes
publish once into the latest queue, retaining interleaved writers and fresh own
IDs. No publication proves game writes, send, inventory effects or server ACK.

Rerender preserves a pending frame. Toggle/profile/destruction invalidate it;
generation and reentrancy guards reject old provider results/callbacks. The
100ms cadence is own UI policy. Source strings, notices, native NPC/selection,
settings/dispatcher/BotSwitch integration, other modes and live acquisition
remain open.

Evidence includes14 new runtime scenarios and an actual checkbox/timer UI test
with manual interleaving, action/post-clock/parent gaps, committed cooldown,
full guard/fresh work byte, NPC stop/notice and profile/stale callback checks.
Four retained REA assemblies match the pinned source;1,136 selected instruction
records are checked across both versions. The validation record preserves the
initial failed test-harness predicate and the successful repaired GUI run.
