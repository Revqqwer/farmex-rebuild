# Invalid-target fallback operand model

The optional EventJoinObservation.fallback_child binds EventFallbackObservation
at worker call00464a20. The own panel accepts the same observation as top-level
`fallback_child` JSON with `values` and `normal_returns`. Only reached fields
are decoded. A detailed child must complete before its separately captured
worker outer return can advance the post timestamp. Late binding after an
opaque return was consumed is rejected.

Source profile1 reads the root slot00553e80, its current ECX and callback slot
00553eac, then calls with no physical pushes. If the first profile byte was
not1, the source reads a fresh second profile byte; only exact2 enters the
longer branch. Unsupported values return without modeled action.

Profile2 checks global00553d18. If zero, it prepares a VirtualAlloc call with
physical PUSH order `(0x40,0x1000,12,0)` and projects its captured EAX into the
global pointer. Both pinned import tables confirm KERNEL32.VirtualAlloc. The
source has no explicit allocation-result zero guard. Projecting a null-address
store follows its operand path; it does not prove a successful native store.

Three components independently read the guarded root and offset globals
00554008/0c/10, call the opaque float reader, reload the allocation pointer,
and project FSTP DWORD stores at pointer+0/4/8. Raw post-FSTP bits are captured;
no component-name convention, x87 rounding, exception handling or memory
identity is invented. The later direct root read is retained even though ECX
is overwritten before the search callback.

The search callback receives a fresh allocation pointer. Full EAX is saved:
zero skips selection/confirmation; nonzero is used unchanged by the selection
callback and physical confirmation pushes `(0,saved_result)`. Callback target,
ECX, argument and normal receipts remain separate. Full helper return registers
are not certified because the event caller ignores them.

All allocation, memory stores and callbacks are inert plans. The own queue
seed is preserved and no new packet is generated by this operand model; this
does not certify that real callbacks have no native queue/game side effects.
No native callback ABI, allocation, memory write, process action or live
compatibility is proved.

Nine tests cover source profile/fresh reads, allocation branches, independent
component pointers and raw bits, discarded reads, saved search result,
callback gaps, parent/outer binding, panel continuation and rejected late
bindings. The hidden own UI smoke exercises an invalid FT target through the
typed profile1 callback plan and confirms no generated local packet.
The audit rechecks740 pinned instruction records, including154 fallback-body
records, two retained REA bodies and both version-specific VirtualAlloc thunks.
