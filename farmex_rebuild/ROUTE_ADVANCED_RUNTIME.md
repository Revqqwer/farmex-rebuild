# Source camp and speed route data

Actual advanced EKLE buttons now append Change Camp and Change Speed Hack rows.
They read reached settings before Add. Camp reads random first; true preempts
manual/text. Otherwise manual true reads text and uses the own pinned scalar
integer/default1 policy. Only the lowDWORD participates: zero becomes Randomize,
other bits format as signed32. No selected mode also produces Randomize.

Speed reads Off, Swift, LightFeet lazily in that priority, mapping0,1,3. First
true skips later reads. No selected mode maps0. Both captions/parameters match
pinned source literals and both second subitems are dash. These edit route data;
they do not change game speed/camp or enqueue game actions.

The shared sink performs blank Add, caption and two subitems, retaining completed
prefixes on an own late setter failure. Camp input failure before Add creates
no row, unlike the previously documented Bekle text-read position. Own parser
default/signed formatting/status/profile errors are not native catch/RTL/CRT/
VCL/SEH certificates. Original runtime identity remains unobserved.

Seven new Python tests cover lazy priority, fresh later flags, no selection,
random short circuit, low32 signed/wrapped/zero/default1 cases, pre-add text
failure, late setter prefix and invalid event/boolean. Actual GUI tests use
radio widgets and EKLE, then save/clear/load through a real owned .R file and
retain the result through profile binding/rerender. Request queue is unchanged.
ROUTE_ADVANCED_RUNTIME_VALIDATION.json records4529 Python tests and full GUI.
Source532 callback instruction records and exact literals/field identities were
checked across both pins. No new REA decompile or live compatibility is claimed.
